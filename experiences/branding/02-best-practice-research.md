# Settled answers for tenant theming and branding

**A customer supplies token values, never a stylesheet.** Every design system that survived multi-tenant theming arrived at the same arrangement: the product publishes semantic tokens, and the customer sets values for a named subset of them. Material's colour roles, Carbon's themes, Primer's functional variables and Tailwind v4's `@theme` block are the same idea with different spellings, and `@neuro/ui`'s sheet already declares its own set in `packages/shared/ui/src/styles/globals.css`. The implication for this stack is that the overridable names are a closed list stated in [`05`](05-interface-and-configuration.md), and everything outside that list keeps the value the design system gave it. A tenant able to supply CSS could break any screen in the product, and no reviewer would see the breakage before a customer did.

**Contrast is checked when the colour is saved.** WCAG 2.2 asks for 4.5:1 between body text and its background, and 3:1 for large text and for the boundary of an interactive control. A brand colour chosen for a letterhead often fails both, and a tenant that saves one has made its own product unreadable for everyone in the tenant at the same moment. So the save path computes the ratio for each override against the foreground it will appear against, and either rejects the value with the measured ratio in the message or derives a foreground that passes. Checking at render time is too late: the person who sees the failure is not the person who caused it.

**An uploaded SVG is a script document.** SVG accepts `<script>`, event-handler attributes, `<foreignObject>` and external references, so an SVG served from the app's own origin runs with that origin's privileges. The three accepted answers are to sanitize the markup server-side against an allow-list, to serve assets from a separate origin that holds no session, or to rasterize on upload and serve the raster. This stack takes the first two together, and [`05`](05-interface-and-configuration.md) names the accepted content types and the origin assets are served from.

**A brand asset is served from our own object store and never fetched from a customer's URL.** [`../../coreservices/render/02-best-practice-research.md`](../../coreservices/render/02-best-practice-research.md) already settled this for the render path, where a remote logo makes a PDF depend on someone else's uptime and turns a slow fetch into a render timeout. The same reasoning covers email, where a remote image is also a tracking vector the recipient's client will block, and the app shell, where a third-party origin in the page widens the content-security policy. Legacy's `whitelabel_logo_url` column invites the opposite ([`01`](01-legacy-pitfalls.md) §2).

**A custom hostname is three states, not one flag.** The DNS record, the issued certificate and the binding to a tenant are separate facts that become true at different times, and an operator needs to see which one is missing. The two ACME challenges have different prerequisites, and conflating them produces a claim flow that stalls. HTTP-01 needs the hostname itself to resolve to the challenge server on port 80. DNS-01 needs a resolvable TXT record at `_acme-challenge.<hostname>`, and the hostname's own A or CNAME record may still be absent. Either way, a host bound before its certificate exists serves a browser warning in place of a sign-in page. The model in [`04`](04-proposed-model.md) therefore gives a branded host an explicit state, and the certificate itself belongs to [`../../operations/sites/`](../../operations/sites/00-sites.md), which already owns where a tenant lives.

**Formatting is CLDR through `Intl`, and the locale is a fallback chain.** `Intl.DateTimeFormat` and `Intl.NumberFormat` are part of the runtime and implement the Unicode locale data, so the stored value is a BCP 47 locale tag plus explicit options. Legacy's integer `date_format` ([`01`](01-legacy-pitfalls.md) §9) means nothing without the constant beside it and covers a handful of the arrangements a customer asks for. The chain runs person, then tenant, then platform, and an unattended job starts at the tenant because it has no person.

**Email has no cascade to rely on.** Mail clients strip `<style>` blocks, ignore external stylesheets, and handle dark mode differently from one another, so a branded message is built from values inlined at send time. What this stack gives comms is resolved values and asset URLs. The template that arranges them belongs to [`../../coreservices/messaging/channels/`](../../coreservices/messaging/channels/00-channels.md), and a brand supplying markup would be a second template engine.

**What does not apply.**

1. **A theme builder.** A screen where a customer arranges components and previews the result is a product of its own, and the requirement here is a logo, a colour and a disclaimer. The admin surface is a form.
2. **Per-person theming.** Light and dark are a viewer preference the design system already handles. A person choosing their own brand colour would defeat the reason a tenant sets one.
3. **Per-tenant CSS compilation.** Building a stylesheet per tenant breaks shared caching and puts a build step in the request path. CSS custom properties set on the document root change the same values at runtime with no build.
4. **Hosting a customer's licensed typeface.** Commercial font licences are priced per domain and per pageview, and serving a customer's file exposes both parties. A tenant chooses from the typefaces the product bundles.
5. **Content-addressed asset storage.** Deduplicating logos across tenants saves nothing at this volume and makes erasure a reference-counting problem.
6. **A brand inheritance hierarchy.** Parent and child brands with cascading overrides is a feature of agency tooling. A tenant has brands, and a binding picks one per surface.
